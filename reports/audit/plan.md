**β decision rule (revised 17 Oct 2026, 12:50, on your instruction, BEFORE any β decision was computed).**
At that moment 1 of 16 screen runs had finished and none had been analysed. The superseded 0.002-DSC tie rule is kept in git history (commit `d316dfa`). The rule is implemented in `analysis/beta_decision.py` and unit-tested in `tests/test_beta_decision.py`.
- **Run score:** max over rounds of the centred 3-round moving-average validation DSC (the value that selects the run's checkpoint).
- **β score:** mean run score over its 2 seeds.
- **Pooled s.d. (per task):** the seed-to-seed s.d. of the run score, pooled across β: sqrt(mean of the per-β variances, ddof = 1).
- **Decision:**
  - **keep the pre-registered default β = 0.5** unless another β beats it by **more than the pooled s.d.**;
  - if several do, choose the highest-scoring one;
  - any within one pooled s.d. of that one are tied, and the tie goes to the **lower round-to-round q_i variance** (per client, averaged over clients and seeds).
- **Shared β:** reported only (each task's selected β within one pooled s.d. of the other's). The per-task β is used.
- **Before the headline is queued,** the numbers and the rule's outcome are written to `results/beta/beta_decision.{json,md}` and to §0.5 below.

**XFedGA CAM definition changed (decision (b), 17 Oct 2026 13:49; recorded before any new run).**
- **New definition:** Grad-CAM at the **full-resolution decoder up-convolution** (`xai.explainability.unet_fullres_cam_layer`, `model.model[2][0]`), explaining the class-1 logit summed over the model's **predicted foreground** (`cam_target = pred`; it falls back to all pixels when the prediction is empty).
- **Where it is used:** the config default for both tasks, and the single CAM definition for q_i, the EC fitness term, validation/test EC and pointing-game logging, and all independent XAI metrics.
- **Evidence:** a **synthetic known-answer test only** (`tests/test_xai_known_answer.py`): a Residual U-Net trained to Dice > 0.8 on synthetic bright squares, 2 training seeds, 5–8 test images. The old layer (`unet_cam_layer`, a half-resolution decoder conv) put 0.05–0.19 of the CAM mass on the lesion, with pointing game 0.38, for either target. The full-resolution layer gives 1.00 and 1.00, insertion > deletion on every image, and a rank-correlation drop under weight randomisation. The all-pixel target puts ~0 mass on the lesion at the old layer.
- **What the choice was NOT based on:** validation or test results of the method. A real validation-slice check (one β-screen checkpoint) was run only after the known-answer finding, as a sanity check.
- **State of the experiments at this decision:**
  - **no headline run existed;**
  - the β screen (old CAM definition) had 3 of 16 runs finished and was stopped after its 4th. Those runs are kept, tagged `oldcam`, and **excluded from all analysis**.
  - The β screen is rerun with the new definition and the same pre-registered β rule.
- **Superseded:** every result before 17 Oct that used EC, pointing game or q_i, including Review-2 (`reports/audit/reaudit.md`, item 6).

**Primary endpoint (pre-registered 17 Oct 2026, 13:21, before any headline run exists; your instruction).**
- **Primary, one per task:**
  - XFedGA vs FedGA (baseline), **test DSC**;
  - case-level paired difference (per-image DSC → per-case mean → mean over the 5 seeds within each case → XFedGA − FedGA);
  - **95% cluster-bootstrap CI over test cases** (10,000 resamples). Prostate: 16 cases; breast: 638 patients.
  - **WIN** if the CI excludes 0 upwards, **LOSE** if it excludes 0 downwards, otherwise **TIE**. Prostate TIE is the pre-registered expectation.
- **Secondary / exploratory, labelled so in every table:**
  - test HD95_norm, EC and pointing game;
  - all independent XAI metrics;
  - every other method pair (XFedGA vs FedAvg, FedGA vs FedAvg, FedProx);
  - all ablations, the random-search control, the β screen, the heterogeneous partition, robustness/DP and parity.

  No multiplicity correction is applied to secondary comparisons. They are reported as exploratory and are not used to claim superiority.
- **Sensitivity for the primary endpoint** (also reported for secondary comparisons): a case-level paired t-interval and a Wilcoxon signed-rank p-value. Any comparison where the bootstrap and t-interval disagree on WIN/TIE/LOSE is flagged in the table.

*(c) Protocol v2: exactly three changes, applied to ALL methods, plus one logging change.*
1. **Fitness subsample 40 → 120** images: one fixed set of ids, shared by FedGA and XFedGA, chosen by the same rule as now (one per patient for breast; evenly spaced per fitness case for prostate).
2. **Local epochs 10 → 2**; rounds stay 15.
3. **Prostate only:** field-of-view crop + z-score intensities.
   - **Crop rule (no ground truth at inference):** after the 0.5 mm in-plane resampling, crop a square of side **S mm centred on the image centre** of every slice, then resize to 384×384.
   - **How S is chosen:** the smallest multiple of 10 mm that contains **every gland pixel of the client training masks** (PROMISE12). This uses training masks only, never validation or test.

4. **Logging only:** w_agg's validation DSC every round (for the GA-overfitting diagnostic).

## 7. `fl_dist/` design (Tier 1, P2)
**Principle.** No algorithm code in `fl_dist/`. Every function that touches weights, q_i, fitness or the GA is imported from `fedga/` / `xai/`. The same functions are called by the custom loop.

| File | Role |
|---|---|
| `fl_dist/client.py` | `XFedGAClient(fl.client.NumPyClient)`. Starts with `--client_id`, `--config` and `--server_address` (from YAML, default `127.0.0.1:<port>`). Loads **only its own client's data**. `fit(parameters, config)`: set weights (keys in `state_dict` order) → `core.local_update` → `core.client_saliency_score` on the fixed q_i subsample → return `(ndarrays, n_i, {"q_i": q})`. `evaluate` is disabled (`fraction_evaluate=0`). Started with `fl.client.start_numpy_client` (Flower 1.7.0) |
| `fl_dist/strategy.py` | `XFedGAStrategy(fl.server.strategy.FedAvg)`, overriding `aggregate_fit`: (1) audit each `FitRes`; (2) convert ndarrays to state dicts; (3) `fedga.aggregate(mode, states, n_i, q_i, beta)`, the same function the custom loop calls; (4) `fedga.run_ga(...)` with the server-held fixed fitness subsample; (5) validation evaluation and the per-round CSV in the same schema as the custom loop; (6) return the winner as `Parameters`. `configure_fit` sends only `{"round", "local_epochs", "seed"}` |
| `fl_dist/server.py` | Builds the model, fitness/validation sets and strategy from YAML; `fl.server.start_server(server_address, config=ServerConfig(num_rounds), strategy)`; saves the validation-selected checkpoint |
| `fl_dist/launch.py` | **One PowerShell command:** `& $py fl_dist/launch.py --config configs/fl_breast.yaml --seed 1`. Finds a free loopback port, writes it into the run config, starts the server, waits for it to listen, then starts one OS process per client. Logs go to `results/fl_dist/<run_id>/{server,client_1,client_2}.log`. Ctrl+C or any non-zero child exit terminates all children (`Popen.terminate` → `kill` after a timeout). Returns non-zero on failure |
| message audit (built into `fl_dist/strategy.py`) | For every round and client: the parameter count, shapes, dtypes and bytes, the metric keys (must be exactly `{"q_i", "client_index"}`), `num_examples` (= n_i), and the config keys sent (`{"round"}`). Writes `message_audit.json` in the run folder; fails the run if anything other than **weights, n_i, q_i and the client index** appears (as built, 17 Oct) |

- **q_i transport.** A float in `FitRes.metrics["q_i"]`, alongside `num_examples` = n_i. This was verified in yesterday's toy run: the server received `{'q_i': 0.1}` and `{'q_i': 0.2}`.
- **Payload.** 1,625,161 float32 parameters ≈ **6.5 MB per client per direction per round**. That is computed from the model's parameter count, not measured; the audit will measure it.
- **GPU sharing (6 GB).**
  - Measured single-process peaks are 0.71–0.73 GB reserved (`timing_summary`), plus a CUDA context per process. The 2-run sharing test (§3) measures the concurrent case.
  - Federated learning here is synchronous: the server's GA runs while clients wait, and the two clients train at the same time. Expected peak ≈ 3 contexts + 2 training + 1 idle model, about 2–3 GB, which fits.
  - The spec requires this to be **measured** in the P2 smoke run, with 2 clients + server at the same time (logging `torch.cuda.max_memory_reserved` per process plus `nvidia-smi`).
  - Fallbacks, in order: (a) clients run sequentially via a file lock around `local_update`; (b) aggregation on CPU on the server, keeping the GA on GPU. The report states which option was used.
- **Cross-machine claim.** Only `server_address` in YAML changes. **Not tested across machines**, and the report says so.
- **Description in all text:** "multi-process federation on a single machine over loopback gRPC".
- **Determinism and parity.**
  - Per-client seeds are derived from (seed, client_id, round).
  - Concurrent GPU training is not bitwise reproducible, so parity is tested statistically: 3 seeds, breast XFedGA, case-level paired difference in test DSC vs the custom loop (bootstrap CI).
  - Proposed equivalence margin: |ΔDSC| < 0.02 (decision Q6).
- **Alternative considered.** Flower simulation (`start_simulation`, Ray). Rejected: the spec requires separate OS processes, and Ray is not installed (an install would need your approval).

**Beta-specific pre-registration (your instruction, 14 Oct).**
- Grid β ∈ {0, 0.2, 0.25, 0.5, 1.0}, 3 seeds, both tasks, all other settings default. q_i is logged per client per round.
- The best β per task is chosen on **validation DSC** (mean of the last 5 rounds, averaged over seeds); ties are broken by the smaller q_i-induced weight variance.
- **One shared β is defensible** if, for each task, the other task's best β lies within the validation-DSC noise of that task's best: |Δ| below 1 seed-SD of the validation mean. Otherwise report per-task β.
- β = 0 makes the aggregation plain FedAvg weighting (q_i is still computed but unused). So E(β = 0) vs E(β*) at identical GA, fitness and annealing settings is the cleanest "weighted aggregation" contrast for RQ3. Note that E(β = 0) is **not** ablation C: C has no annealing.
